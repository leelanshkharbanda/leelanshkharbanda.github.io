03 ENTRIES

01 Simulator

Chronos-DSP

Wireless propagation simulator with an Elixir/Phoenix control plane and a Rust NIF DSP data plane.

A 3D scene of transmitters, receivers and planar walls is driven from LiveView while signal processing runs server-side. The model covers line-of-sight, image-source reflections, knife-edge diffraction, wall transmission, material attenuation and Doppler.

DATA PLANE
Rust NIF called via render_rx_block/5
SIGNAL
Seeded QPSK + AWGN, reproducible BER

render_rx_block/5 runs on a dirty CPU scheduler with artifact-magic checking and a deterministic pure-Elixir reference that mirrors sample order, interpolation, rotation and RNG.

Scope note. This is a simulator, not a live radio and not a deployed telecom product.

02 Live demo

Modulation Studio

A browser DSP visualizer for waveforms, FFT magnitude spectra and constellation plots.

A terminal-style browser instrument: waveforms, spectra and constellations update as you change the channel. Impairments include AWGN, fading, and carrier/phase offset; digital schemes report BER/SER and analog ones report correlation.

NAMED SCHEMES
AM DSB-LC/DSB-SC, FM, PM, ASK, FSK, BPSK, QPSK, 16-QAM
RECEIVER
Optional PLL with timing recovery

Analytics are off by default and Do Not Track / Global Privacy Control are honoured. There is a working static-site demo.

Scope note. Named schemes only — no hard scheme count is claimed, because repository metadata and the README disagree.

03 Simulation

MoE Memory Wall

A computer-architecture course project on expert prefetching across the CPU DRAM / HBM boundary.

Studied Mixtral-8x7B decode with experts offloaded to CPU DRAM, using LLMSimulator and an SSD-offloading fork. The policy combines a calibrated speculative gate with history fallback, guided replacement, preemption and a feedback throttle.

REPORTED RESULT
1.27× at C=64 on TinyMoE prose vs on-demand LRU
TEAM
CA Project 2, Group 24 — group course project

The submitted table reports simulated H100/A100 configurations alongside energy and DRAM→HBM traffic costs.

Scope note. Everything is simulation; no GPU measurements and no production deployment. Numbers are reported by the project's simulation with their configuration intact.

Notes

A WORKING POSITION

Signal processing and computer architecture ask the same question: what does the machine actually do? Channel, cache, counter, clock — I model those layers in software instead of treating them as abstraction.

01

Model the channel

Start with the physical layer: paths, noise and the limits they impose.

02

Measure the counters

Prefer a trace or a reported figure to an untested assertion.

03

Keep data local

Inference and storage can stay on the device; tools should respect that.
