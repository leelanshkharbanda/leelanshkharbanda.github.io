PERSONAL PROJECT · RELEASED

Chronos-DSP: from geometry to simulated IQ — Personal project

A personal simulation that makes geometric propagation inspectable from scene geometry to simulated QPSK and BER, with a headless API and test evidence. No RF calibration is claimed.

Question

01 / 05

How can ray geometry become an inspectable, deterministic received-signal simulation without implying hardware accuracy?

Mechanism

MOVING PARTS

A scene contains transmitters, receivers and planar walls. The channel layer derives candidate paths — line of sight, image-source reflections with a bounded bounce count, knife-edge diffraction around blocking edges and transmission through walls — each carrying geometry and DSP-relevant fields such as delay, gain and Doppler, with a path cap keeping crowded scenes bounded. Those paths feed a QPSK chain: fractional-delay interpolation, Doppler phase rotation and complex additive Gaussian noise under an explicit seeded generator. A Rust NIF renders on a dirty CPU scheduler while a pure-Elixir reference mirrors the sample-order, interpolation, rotation and RNG contract; LiveView owns the supervised session and a headless JSON/CSV API exposes the same model outputs.

This is a personal build. The repository, release, tests and CI logs carry the contribution claim; the two renderers share one numerical contract. No team size is asserted.

Guardrail

LIMITS

Geometric propagation and material losses are illustrative; the model is not calibrated against RF measurements

  • No live, over-the-air or hardware measurement and no external deployment is claimed.
  • There is no frequency-selective channel, antenna or link budget, OFDM, or FEC in the documented scope.
  • Dirty-CPU scheduling and the reference fallback do not establish hard-real-time deadlines or latency guarantees.
  • The named-scene store is capped and ephemeral; the public API has documented authentication and rate-limit gaps.
  • Repository screenshots are not reused; the portfolio visual is an original diagram.
