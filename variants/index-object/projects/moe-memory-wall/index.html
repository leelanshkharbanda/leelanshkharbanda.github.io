MoE Memory Wall: Prefetching Experts Under an HBM Budget — Group coursework

A group coursework simulation of expert prediction, HBM caching and prefetching across TinyMoE prose/code, Mixtral-calibrated and uniform routing under a constrained memory budget.

Question

01 / 05

When expert weights exceed HBM capacity, can training-free prediction and prefetching reduce decode stalls without changing routing?

Mechanism

MOVING PARTS

LLMSimulator had no learned router, so the group supplied routing traces: recorded TinyMoE (a Mixtral topology trained on Tiny Shakespeare and CPython code), a Mixtral-calibrated generator fitted to published temporal-locality statistics, and uniform routing as a null. Causal training-free predictors — a calibrated speculative gate with a history fallback — fed a Python discrete-event timeline with a per-layer LRU HBM cache, one copy link, demand priority, next-layer prefetch, guided replacement, preemptible copies and feedback throttling. Prefetching never changed which experts were routed.

This was group coursework, not a solo build. "Group 24" is a group identifier rather than a verified headcount, and the project did not build LLMSimulator. Contribution and credit remain shared.
