Chronos-DSP

Platform
Elixir · Phoenix · Rust NIF
Method
Seeded, reproducible simulation
Scope
Simulator — not a live radio

An Elixir/Phoenix control plane drives a Rust NIF DSP data plane. The channel model covers line-of-sight, image-source reflection, knife-edge diffraction, transmission and material attenuation, with QPSK, AWGN and BER in a seeded pipeline.

A deterministic pure-Elixir reference mirrors the NIF’s sample order, interpolation, rotation and RNG, so the result can be checked without the native path.

Scope note: this is a simulator. It does not receive or transmit over-the-air signals.

Source: github.com/leelanshkharbanda/Chronos-DSP ↗

Modulation Studio

Form
Terminal-style browser visualizer
Views
Waveform · FFT spectrum · constellation
Scope
Named schemes; no count asserted

A browser DSP visualizer with a terminal feel. Waveforms, FFT magnitude spectra and constellations are drawn for named schemes including ASK, FSK, BPSK, QPSK and 16-QAM, with AWGN, fading and carrier/phase offset shown in the same view.

Digital schemes report BER/SER and analog schemes use correlation; an optional adaptive receiver combines a PLL with timing recovery. Analytics stay off by default and honor Do Not Track and Global Privacy Control.

Scope note: named schemes only. No hard scheme count is claimed.

Live demo: Modulation Studio ↗ · Source: GitHub ↗

MoE Memory Wall

Team
Group course project · CA Project 2, Group 24
Method
Simulated Mixtral-8x7B decode
Scope
Simulation — not a GPU measurement

A group course project studying expert prefetching across the CPU DRAM → HBM boundary in offloaded Mixtral-8x7B decoding. A calibrated speculative gate with history fallback copies predicted experts toward HBM ahead of use.

The project reports 1.27× at C=64 on TinyMoE prose against on-demand LRU, alongside explicit energy and DRAM→HBM traffic costs. Every figure comes from simulation; no real GPU measurement is claimed.

Scope note: group course project (CA Project 2, Group 24). The reported 1.27× at C=64 on TinyMoE is a simulation result, not a GPU measurement.

Source: github.com/leelanshkharbanda/MoE-Memory-Wall-CA-Project ↗

03THINKING

Working notes

On method

State the boundary

A simulator earns trust by saying what it is not. The propagation work names its paths and the memory-wall work names its simulator; the limit stays visible beside the result.

Keep a legible fallback

A native fast path is only as trustworthy as the reference beside it. Mirroring sample order in plain Elixir makes the DSP result checkable without the NIF.

Keep data close

Local-first is a constraint with consequences: on-device inference and vector memory change what a tool can honestly promise about privacy.
