DS–01 / PHYSICAL LAYER

Chronos-DSP

SIMULATOR · NOT A LIVE RADIO

Layer
Control plane + DSP data plane
Stack
Elixir / Phoenix · Rust NIF
Domain
Propagation · modulation · BER

A real-time wireless propagation simulator: an Elixir/Phoenix control plane drives a LiveView scene while a Rust NIF runs the signal-processing data plane server-side.

The channel model covers line of sight, specular reflections via the image-source method, knife-edge diffraction, transmission, material attenuation and Doppler. QPSK, AWGN and BER run through a seeded, reproducible pipeline.

render_rx_block/5 dispatches the NIF on a dirty CPU scheduler with artifact-magic checking. A pure-Elixir reference path mirrors the NIF's sample order, interpolation, rotation and RNG so results can be cross-checked.

This is a simulator. It does not receive over-the-air signals and is not a deployed radio product. No accuracy figure is claimed here beyond what the repository itself documents.

DS–02 / VISIBLE DSP

Modulation Studio

LIVE BROWSER DEMO

Layer
Browser visualizer
Views
Waveform · FFT · constellation
Signal
Named schemes only

A browser DSP visualizer with a live static-site demo. Analog schemes include AM DSB-LC, AM DSB-SC, FM and PM; named digital schemes include ASK, FSK, BPSK, QPSK and 16-QAM.

It draws waveforms, FFT magnitude spectra and constellations, and computes BER/SER for digital schemes and correlation for analog ones.

Impairments include AWGN, fading and carrier/phase offset. An optional adaptive receiver combines a PLL with timing recovery, exposed in the browser next to the three views.

Source descriptions disagree on the exact digital-scheme count, so this page names schemes instead of asserting a total. Analytics are off by default and honor Do Not Track / Global Privacy Control.

DS–03 / MEMORY WALL

MoE Memory Wall

SIMULATION · GROUP COURSE PROJECT

Layer
Computer architecture
Setting
CA Project 2, Group 24
Method
Trace-driven simulation

A group course project studying Mixtral-8x7B decode with experts offloaded to CPU DRAM, using LLMSimulator and an SSD-offloading fork. The final submission adds training-free expert predictors and a prefetcher.

The project reports 1.27x at C=64 on TinyMoE prose against on-demand LRU, with energy and DRAM→HBM traffic costs shown alongside.

The policy combines a calibrated speculative gate with history fallback, guided replacement, preemption and a feedback throttle. Results are reported across platform × workload × batch × capacity configurations.

Everything here is simulation; no GPU is needed and no GPU measurement is claimed. It is a group course project, not sole authorship and not a production deployment.

04 / NOTEBOOK

Thinking, in the margins.

N–01 / REPRODUCIBILITY

A simulator earns trust by being reproducible.

A seeded pipeline and a deterministic reference path mean a result can be checked twice. In Chronos-DSP the fallback mirrors the NIF's sample order, interpolation, rotation and RNG; agreement between two implementations is a more useful claim than a single pretty plot.

MARGIN → trust the check, not the picture.

N–02 / MEASUREMENT

Measure before you accelerate.

The MoE study reports a speedup together with energy and traffic costs, and states that the numbers come from simulation. Acceleration without the cost column is only half an experiment.

MARGIN → a ratio needs its denominator.

N–03 / LOCAL-FIRST

Keeping data local is a design constraint, not a slogan.

Life OS keeps inference and user data on the device. That choice shapes the stack as much as any feature list: the model boundary, the storage layer and the trust model all move to the machine in front of you.

MARGIN → the boundary is the feature.
