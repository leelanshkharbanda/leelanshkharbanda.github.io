# Dithering-led portfolio references

**Access date for every source: 2026-11-26.** Five live references were inspected as pages and, where available, through their publicly served first-party code. Served bundle URLs are version-specific. This is research, not an accessibility audit of the reference sites. No wording, code, or assets were copied.

## Strongest recommendations

1. **Use dithering as a material system, not a hero filter.** Aonnoy Sengupta connects distinct raster materials to four ways of working; this is the best model for making the treatment carry personal meaning.
2. **Make one bounded, inspectable effect the signature.** Christen Dijoux’s cursor-sensitive ordered-dither scene is strong because it also appears in his component lab and has a deliberate static/reduced-motion path.
3. **Apply the treatment to real work.** Lydia Leiwang’s filtered showreel and Maxime Heckel’s shader studies make the effect evidence of craft. For this portfolio, use original project diagrams, screenshots, or hardware traces—never generic retro imagery.

## Examples

### 1. Christen Dijoux — ordered dithering as a personal lab

- **Exact URL:** <https://christendijoux.com/>; component lab: <https://christendijoux.com/lab>. **Accessed:** 2026-11-26.
- **Observable mechanism:** The hero raymarches a noisy spherical form, then renders it through an 8×8 Bayer threshold. Pointer position changes rotation/light and the raster cell size, creating a finer-grid lens near the cursor; scroll changes scale and contrast. The served code uses a static halftone PNG when WebGL is unavailable, quarter-resolution pixelated rendering on mobile/coarse pointers, a desktop DPR cap of 1.75, an approximately 32 ms frame throttle, intersection-based pausing, and a static redraw path for reduced motion. Source: [DitherHero bundle](https://christendijoux.com/assets/DitherHero-yLhaMYyl.js).
- **Why it is personal:** Dijoux presents himself as a full-stack/AI engineer who also cares about interfaces. The same raster language appears in the journey globe and project thumbnails, while the lab exposes the hero as a named, dissected component. The effect therefore demonstrates a stated blend of engineering and design rather than acting as unrelated decoration. Evidence: [live portfolio](https://christendijoux.com/) and [lab](https://christendijoux.com/lab).
- **Original adaptation:** Build a **signal-to-pattern project card** around an original project artifact: a cursor lens temporarily resolves the ordered dots into a clean schematic, while focus/click opens the ordinary DOM case study. Label simulation results and measured results explicitly; do not let the effect obscure that distinction.

### 2. Lydia Leiwang — a showreel processed into a visual voice

- **Exact URL:** <https://lydialeiwang.com/>. **Accessed:** 2026-11-26.
- **Observable mechanism:** A hidden local video is sampled into a coarse grid; luminance selects filled squares, smaller squares, diamonds, X marks, dots, or empty cells. This is more accurately **luminance-to-geometric-glyph quantization** than Bayer dithering. The renderer uses 8 px cells, a 24 fps cap, repeated low-resolution `getImageData`, theme/palette-aware colors, and an `IntersectionObserver` before starting. Clicking the preview stops the canvas loop and replaces it with a controllable Vimeo player. A site-wide ASCII cursor trail reuses the same shape vocabulary. Sources: [index markup and inline renderer](https://lydialeiwang.com/index.html), [shared interaction code](https://lydialeiwang.com/shared.js?v=20261117e).
- **Why it is personal:** Leiwang’s positioning is brand, motion, and launch work for technical products. The showreel is actual work output, so processing it makes the portfolio itself a motion-design sample. The project list supplies the concrete context that keeps the treatment from becoming a generic retro skin. Evidence: [live portfolio](https://lydialeiwang.com/) and [first-person About page](https://lydialeiwang.com/about.html).
- **Original adaptation:** Create an **evidence resolution ladder** for one motion-heavy project: normal playback → rasterized playback → frame-by-frame DOM explanation. Keep a poster frame, transcript, and plain controls available. The pattern should clarify timing or system behavior, not merely make the work look aged.

### 3. Aonnoy Sengupta — raster materials mapped to ways of working

- **Exact URL:** <https://aonnoysengupta.com/>. **Accessed:** 2026-11-26.
- **Observable mechanism:** Four classical-head models cycle through custom print-like materials. The source includes object-space blue-noise thresholding, a rotated halftone-dot screen, binary digit rendering, and an ink treatment. A stepped timeline advances the models; horizontal pointer dragging scrubs their rotation and style changes; light/dark mode changes ink and paper. The implementation renders some stages at reduced resolution, caps DPR at 2, loads assets during idle time, pauses offscreen/hidden, checks reduced-motion/save-data/hardware conditions, and abandons the scene if a 24-frame timing sample exceeds 40 ms. Sources: [hero mount](https://aonnoysengupta.com/_astro/mount.CwfNP9qp.js), [page controller](https://aonnoysengupta.com/_astro/index.astro_astro_type_script_index_0_lang.CvaFGwaK.js), [reduced-motion/theme helper](https://aonnoysengupta.com/_astro/app.BrJK0YYW.js).
- **Why it is personal:** The page identifies a one-person design-and-engineering practice, and the four figure captions map to “join your team,” “make it faster,” “build it,” and “fix it.” Raster treatment becomes a navigable metaphor for services, while the live material changes demonstrate range. The page also credits the source and license of the Hephaestus model. Evidence: [live portfolio](https://aonnoysengupta.com/).
- **Original adaptation:** Design **four engineering materials** from original artifacts: ordered dots for signal paths, stipple for measured hardware, hatch for constraints, and clean linework for evidence. Let users scrub between problem → constraint → mechanism → result. Keep every label and case study in DOM text.

### 4. Maxime Heckel — the effect as research, teaching, and portfolio identity

- **Exact URL:** <https://maximeheckel.com/>. **Accessed:** 2026-11-26.
- **Observable mechanism:** The served `DotEffect` samples an 8 px grid, maps luma to three dot radii, blends in animated fractal noise, and displaces UVs within a cursor-centered radius. The portfolio scene shifts among halftone, blueprint, and neon states; its project index includes “Dithered Waves.” Heckel’s own articles explain ordered/Bayer dithering, blue noise, quantization, pixelization, halftone, and cursor-driven displacement. Sources: [served portfolio scene code](https://maximeheckel.com/_next/static/immutable/chunks/390m96ui6oo__.js), [dithering study](https://blog.maximeheckel.com/posts/the-art-of-dithering-and-retro-shading-web/), [halftone study](https://blog.maximeheckel.com/posts/shades-of-halftone/).
- **Why it is personal:** Heckel explicitly frames the portfolio around frontend engineering, WebGL, shaders, unfinished experiments, and teaching. The effect is both an intro and a subject of his writing, so it expresses a sustained practice rather than a one-off visual trick. Evidence: [live portfolio](https://maximeheckel.com/).
- **Original adaptation:** Add one **shader study shelf** with before/after views and three meaningful controls—algorithm, cell size, and source artifact. Use an original project screenshot or generated trace as the source. Default to a static comparison and make motion opt-in.

### 5. Simone Andreotti — a parameterized dithering workbench

- **Exact URL:** <https://lab.simone-dev.com/dithering/>; parent portfolio/lab index: <https://lab.simone-dev.com/>. **Accessed:** 2026-11-26.
- **Observable mechanism:** A Three.js subject—sphere, cube, torus, or full-screen noise—passes through selectable Bayer 2×2/4×4/8×8, checker, crosshatch, random-noise, and ASCII patterns. Controls expose posterization, monochrome/RGB/split-RGB output, threshold bias/noise, palette mixing, pixelation, blur, thermal mapping, cel shading, pencil lines, recursive grids, pixel sweep, bloom, and frame time. The page caps DPR at 2 and disposes resources on `pagehide`. Sources: [demo controller](https://lab.simone-dev.com/_astro/dithering.astro_astro_type_script_index_0_lang.CfVK9LRH.js), [postprocessing implementation](https://lab.simone-dev.com/_astro/ditherPostprocessing.xdBQS1rc.js).
- **Why it is personal:** This is one of 84 experiments in Andreotti’s developer portfolio. The workbench turns algorithmic knowledge into something visitors can inspect and manipulate, which is direct evidence of creative-development skill. Evidence: [lab index](https://lab.simone-dev.com/).
- **Original adaptation:** Build a deliberately smaller **evidence processor** with three controls and a few presets. Apply it to a project-owned image or trace, not a stock photo. Unlike this reference, provide a page-specific reduced-motion/static mode and stop rendering when hidden.
- **Caution:** The inspected demo runs a continuous animation loop and did not expose a page-specific reduced-motion branch. The parent offers an accessible version, but the control-heavy experiment should be treated as an interaction reference, not copied wholesale.

## Authoritative implementation constraints

### Canvas and image processing

- **Choose the rendering path by workload.** Canvas 2D is appropriate for small grids and one-shot image edits; WebGL is appropriate for repeated per-pixel work. `getContext()` can return `null`, so a real image/text fallback is required. `willReadFrequently: true` forces software 2D rendering and should be reserved for repeated readbacks. Cross-origin images can taint the canvas and make `getImageData()` throw `SecurityError` unless CORS permits the read. Sources: [getContext](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/getContext), [getImageData](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/getImageData).
- **Reduce pixels before processing.** An RGBA `ImageData` buffer costs `width × height × 4` bytes. Downsample to the dither grid before CPU loops; for static portfolio images, precompute the result at build time instead of processing on every visit. `createImageBitmap()` supports resized output and pixelated/low/medium/high quality; release discarded bitmaps with `close()`. Sources: [ImageData layout](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Pixel_manipulation_with_canvas), [createImageBitmap](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap), [ImageBitmap.close](https://developer.mozilla.org/en-US/docs/Web/API/ImageBitmap/close).
- **Keep expensive work off the critical path.** Pre-render static layers, cache scaled images, use integer coordinates, avoid per-frame image scaling, and use `requestAnimationFrame` rather than timers. `OffscreenCanvas` can move rendering and pixel work into a worker. Sources: [canvas optimization](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas), [OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas).
- **Budget GPU passes and readbacks.** A smaller back buffer with upscaling is an accepted quality/speed tradeoff. Avoid synchronous `readPixels`, repeated parameter queries, and per-frame allocations; use parallel shader compilation where supported; dispose textures, buffers, programs, and contexts. Handle `webglcontextlost`. Note the platform nuance: `alpha: false` can help 2D canvas but can be expensive for WebGL on some platforms. Sources: [WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices), [context loss](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/webglcontextlost_event).
- **Do not equate visual complexity with quality.** Paper’s first-party CMYK writeup recommends one sample at each dot center to keep dots round; its overlapping/gooey mode reaches 36 texture samples per pixel and is explicitly costly. Start with a simple one-pass treatment and add neighbors only after measurement. Source: [Paper: Exploring retro print with CMYK Halftone](https://paper.design/blog/retro-print-cmyk-halftone-shader).

### Reduced motion and flashing

- `prefers-reduced-motion: reduce` communicates a request to remove, reduce, or replace non-essential motion. Honor it in JavaScript as well as CSS, listen for changes, and provide a static dither frame rather than merely slowing the animation. Source: [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion).
- **WCAG 2.2 SC 2.2.2 (A):** automatically moving/blinking/scrolling content that runs for more than five seconds alongside other content needs pause, stop, or hide unless essential. **SC 2.3.3 (AAA):** interaction-triggered motion must be disableable unless essential; this is the strongest target for cursor lenses, parallax, and scrub effects. Sources: [Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html), [Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html).
- **WCAG 2.2 SC 2.3.1 (A):** no more than three flashes in any one-second period, or remain below the general/red-flash thresholds. Avoid full-field, high-contrast noise flicker; do not rely on the fine-pattern exception as a design strategy. Source: [Three Flashes or Below Threshold](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html).

### Contrast and text legibility

- **WCAG 2.2 SC 1.4.3 (AA):** text needs 4.5:1 contrast, or 3:1 when at least 18 pt regular/14 pt bold. Thresholds must not be rounded. For patterned backgrounds, measure the local background behind the letters and use a solid panel/overlay when necessary. Source: [Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [technique G18](https://www.w3.org/WAI/WCAG22/Techniques/general/G18).
- **Dithering has a specific contrast rule:** when dithering occurs after delivery, evaluate the source color; when colors are dithered at the source, use the average R, G, and B values. This is not permission to place ordinary text over moving dots—DOM text on a stable high-contrast surface remains the safer implementation. Source: [relative-luminance definition, Note 4](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#dfn-relative-luminance).
- **WCAG 2.2 SC 1.4.11 (AA):** controls, state/focus indicators, and meaningful graphical parts need 3:1 against adjacent colors. Test focus and selected states against the actual dither palette. Source: [Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
- **Canvas is a bitmap, not semantic content.** It does not expose drawn objects like HTML; canvas text blurs under magnification and is treated as an image of text for text-spacing purposes. Keep headings, project evidence, controls, and descriptions as DOM text with canvas as enhancement. Source: [Canvas API accessibility concerns](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API), [Text Spacing applicability](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html).
- Preserve **200% text resize** (SC 1.4.4, AA), reflow at **320 CSS px** for vertically scrolling content (SC 1.4.10, AA), and no loss under line height 1.5, paragraph spacing 2, letter spacing 0.12, and word spacing 0.16 (SC 1.4.12, AA). Sources: [Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html).

### Performance and lifecycle

- Drive animation from the `requestAnimationFrame` timestamp so speed is refresh-rate independent; cancel work when offscreen, hidden, paused, or disposed. Background tabs already suspend RAF in most browsers, but explicit intersection/visibility handling also protects foreground battery and responsiveness. Sources: [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), [canvas optimization](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas).
- Use **RAIL as a frame/input budget, not a WCAG rule:** about 10 ms to produce a frame within a 16 ms total budget, event processing within 50 ms for a visible response inside 100 ms, and idle work in chunks no longer than 50 ms. Source: [RAIL](https://web.dev/rail).
- Protect field targets at the 75th percentile, segmented mobile/desktop: **LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1**. Reserve the canvas aspect ratio, lazy-init the effect, and show a lightweight placeholder so it cannot delay the main content or shift layout. Sources: [Core Web Vitals](https://web.dev/articles/vitals), [INP](https://web.dev/articles/inp).
- A practical degradation ladder is: precomputed static raster → low-resolution canvas → shader-based real-time version. Reduce DPR/render target before reducing content legibility, and offer quality/static controls when resource constraints are detected.
