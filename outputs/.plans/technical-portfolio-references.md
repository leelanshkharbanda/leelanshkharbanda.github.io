# Research Plan: Technical Portfolio References

## Questions

1. Which award-recognized portfolios demonstrate excellent technical storytelling, visual identity, and interaction without obscuring the work?
2. What specific implementation patterns are observable in their public HTML/CSS/JavaScript, and which are practical to adapt independently?
3. Which patterns are accessible, resilient, and performant enough for a production portfolio?
4. Which creative directions best fit Leelansh Kharbanda’s verified work in DSP, hardware security, computer architecture, and local-first software?

## Strategy

- Run four complementary research streams in parallel: award-platform discovery, independent technical/editorial portfolios, implementation inspection, and accessibility/performance/buildability.
- Require primary-source URLs and direct page/source evidence; use listicles only for discovery.
- Inspect public JavaScript bundles for at least three selected references where technically accessible. Record behavior and architecture, never copied source code.
- Synthesize the evidence into three creative directions and one recommendation, then verify citations and claims independently.

## Acceptance Criteria

- [x] At least six references are supported by primary pages, with award or gallery context where claimed.
- [x] At least three references include direct public source/bundle inspection evidence.
- [x] Every critical claim has source support; implementation inferences are labeled.
- [x] Accessibility and performance risks are covered with authoritative guidance.
- [x] Recommendations reflect the actual GitHub project evidence and avoid unsupported personal claims.
- [x] Three directions are distinct and ranked for practical buildability.
